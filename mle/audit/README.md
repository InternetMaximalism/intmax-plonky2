# Current wire-v3 Lean audit

Target: submodule main `becfe98e37c76e62f02f1aa7a417c7b06840db67`.
The implementation body is `b569e0d7`, and the protocol is `MLEWHIR3`.
The `V2` in file names is an API-generation name; it does not mean that old wire v2 is accepted.

**Status: a partial executable model and deterministic properties have been proved.
Lean-ification of the whole implementation, formal equivalence with Rust/Solidity, and proof of cryptographic soundness are not complete.**

We do not repurpose the old audit as a proof about the current implementation. The ordinary `lake build` and CI inspect the current
`Audit.lean`. The July models, the axiom on the number of roots, and the old findings are separated into
[historical material](HISTORICAL-README.md) and an explicit `HistoricalAudit` target.

Separately, we keep in REPORT a record of regenerating all 1370 non-toolchain-dependency modules as of the 40-model point into a fresh output and
checking all 1019 theorems using that output alone. The 11 pinned display JS data files and
the Lean toolchain remain inside the trust boundary in that check as well, and we distinguish that from the check scope of the models added afterwards.
The fresh source regeneration check is run with `mle/audit/fresh-source-audit.py --run` (a reimplementation of the old temporary
runner; the 29 self-checks are in `test-fresh-source-audit.py`). It recompiles all non-toolchain modules from source into an empty output location,
does not include the existing `.lake/build` in the search path, confirms the import resolution of each module with `lean --deps`,
re-probes all theorems, and writes receipts to `~/.local/share/wire3-fresh-source/`.
Filling holes with `sorry`, `admit`, custom axioms, or `native_decide` is not permitted.
The only global logical axioms permitted are `propext`, `Classical.choice` and `Quot.sound`.
All 18 tables / 1147 words of Poseidon/Coset are compared verbatim with Solidity, and Poseidon is compared with Rust as well.
This is a continuing check of constant extraction, and not formal equivalence of the compiler or of the source as a whole.

**Even if the axiom list is short, the arguments of the theorems and the Engine observations remain as assumptions.**
Hash collation is change detection, and does not prove formal equivalence of the code and the Lean models.
Nor does it turn unproved WHIR soundness into something proved by `Engine.whirTail = true`.
